# Wedding Quest — личные материалы для игры

Заполнить перед финализацией игры. Не нужно самостоятельно рисовать спрайты, резать анимации, удалять фон или монтировать музыку. Передайте оригиналы безопасным способом; агент изготовит runtime-версии. Не помещайте исходники в публичный git или в `public/`. Папка `private-input/` должна быть исключена из git и сборки. Согласуйте передачу личных изображений внешним генераторам отдельно.

## 2. Фото персонажей (P0)

Ориентир: 3–6 качественных фотографий каждого человека и 3–5 каждого питомца. Достаточно резких обычных фото без сильного фильтра, лучше от 1000 px по длинной стороне; не нужны специально сделанные студийные кадры. Допустимо повторно использовать одну общую свадебную фотографию для двух героев. Не загружать чувствительные материалы, если их использование не нужно.

### Невеста — `characters/bride/`
- [ ] Лицо анфас или 3/4 при хорошем освещении.
- [ ] Профиль или боковой ракурс.
- [ ] Свадебное платье целиком, желательно включая обувь.
- [ ] Причёска, украшения, фата и букет (отдельно, если не видны).
- [ ] Узнаваемые детали: цвет волос, силуэт платья, особенности, которые нельзя менять: ______
- [ ] Черты характера/фраза/привычка для игровых анимаций: ______

### Жених — `characters/groom/`
- [ ] Лицо анфас или 3/4.
- [ ] Профиль.
- [ ] Свадебный костюм в полный рост, обувь.
- [ ] Особенности костюма (галстук, бабочка, бутоньерка и т. п.).
- [ ] Узнаваемые детали (волосы, борода, очки и т. п.): ______
- [ ] Черты характера/фраза/привычка: ______

### Питомцы — `characters/cat_1/`, `characters/cat_2/`, `characters/bulldog/`
Для каждого отдельно:

- [ ] Спина, хвост, лапы или необычные пятна, если они важны.
- [ ] Фото с характерной позой (лежит, спит, играет, просит еду).
- [ ] Относительный размер (можно общее фото или словесное описание).

## 4. Реальная история колец (P0)

Заполните короткий рассказ, чтобы агент не исказил реальный случай:

1. Когда и при каких обстоятельствах обнаружилась пропажа?
2. Кто первым начал искать? Где искали сначала?
3. Что делал каждый из вас? Какие были смешные моменты?
4. Кто был гостем с курткой, как кольца оказались у него? Можно ли назвать его в игре?
5. Кто и как в действительности обнаружил кольца?
6. Какие фразы реально прозвучали? Если не помните, так и написать.
7. Что произошло после находки?
8. Какие части истории не хочется показывать или драматизировать?

Ответ: ______

## 6. Музыка

`audio/` — вам необязательно готовить всю фоновую музыку. Главная задача — выбрать значимую финальную композицию и передать легально доступный аудиофайл или указать предпочтение для оригинального трека. Право слушать музыку или подписка на стриминг не дают автоматически права включать её в веб-игру. Если права не подтверждены, используйте оригинальную композицию либо лицензию, допускающую такой формат. Для всех треков указать автора, источник, условия использования и атрибуцию. Не обходить DRM.

| ID | Что выбрать | Рекомендуемый формат | Кто готовит |
|---|---|---|---|
| intro | Спокойное свадебное вступление, 45–90 с, loop | WAV / качественный оригинал | Агент |
| bride | Лёгкий игривый мотив, 60–120 с, loop | WAV | Агент |
| groom | Энергичное комичное приключение, 60–120 с, loop | WAV | Агент |
| mystery | Интрига, затем разрешение, 60–120 с, loop | WAV | Агент |
| finale | Ваша песня либо оригинальная романтическая композиция, 60–180 с | WAV/FLAC/MP3 высокого качества | Владелец выбирает, агент адаптирует |

- [ ] Название и исполнитель свадебной/значимой композиции: ______
- [ ] Почему эта композиция важна: ______
- [ ] Желаемый отрывок/момент вступления (если разрешена адаптация): ______
- [ ] Файл или источник лицензированной версии: ______
- [ ] Подтверждённые условия использования: ______
- [ ] Если права недоступны, настроение оригинального финального трека: ______
- [ ] Предпочтение по общей музыкальной стилистике: ______

Не конвертировать оригиналы в низкобитрейтные файлы. Агент создаёт оптимизированные копии, проверяет звук в браузере и бесшовность петель. Если генерация звука недоступна, агент подбирает разрешённые ассеты и ведёт реестр, не выдавая неподтверждённые права за факт.

## 7. Персональные звуки (P1)

- [ ] Мяуканье первого кота, 2–3 короткие записи.
- [ ] Мяуканье второго кота, 2–3 записи.
- [ ] Лай/сопение/храп бульдога, 2–3 записи.
- [ ] Опционально смешная фраза/запись со свадьбы с разрешения участников.

Подойдёт телефонный диктофон (M4A/WAV). Тихая комната, 1–2 секунды тишины до и после, без музыки или громкого фона. Не провоцировать питомцев ради записи. Агент обрежет, нормализует и добавит игровые варианты.

## 8. Рекомендуемая структура входных материалов

```text
private-input/                  # хранить локально, не публиковать
  characters/
    bride/
    groom/
    cat_1/
    cat_2/
    bulldog/
  wedding/
    venue/
    details/
    guest/                      # только с разрешения
  memories/
  finale/
  audio/
    music/
    pets/
    voice/
  personal_assets_checklist.md  # заполненный этот файл
  permissions.md               # ограничения, авторство, согласия, лицензии
```

Имена файлов могут быть простыми: `bride_full.jpg`, `cat_1_left.jpg`, `memory_01.jpg`, `finale.jpg`, `bulldog_snore_01.m4a`. Не нужно удалять фон и обрезать фото самостоятельно. В релизе агент использует только одобренные производные изображения и звук. Удалить EXIF/GPS из релизных фото; не копировать эту папку в `dist`.

## 9. Минимальный пакет, если времени мало

- [ ] 2–3 фотографии каждого из пяти персонажей (10–15 всего).
- [ ] Реальная история потери/находки колец, описание куртки, имена и дата.
- [ ] 6 фотографий воспоминаний (или 3 при согласованном сокращении) и подписи.
- [ ] Одна любимая свадебная фотография.
- [ ] Личное поздравление.
- [ ] Выбранная финальная музыка с подтверждённым разрешением либо решение использовать оригинальный трек.
- [ ] Согласованные правила использования фото, образов и доступа к игре.

Пока материалы собираются, агент может работать над graybox, физикой, механиками, сохранениями и тестами на временных ассетах.

## 10. Перед вручением подарка

- [ ] Проверены лица, наряды и все три питомца.
- [ ] История не искажает факты; гость не изображён вором.
- [ ] Имена, дата, подписи и поздравление правильные.
- [ ] Музыка работает после первого действия; громкость комфортна.
- [ ] Игра полностью проходима без сбора секретов, есть безопасные чекпоинты.
- [ ] Проверен телефон/ноутбук получателя и доступ к игре.
- [ ] Исходные фото, личные метаданные и тестовые заглушки не попали в сборку.
- [ ] Если сайт закрытый — анонимный пользователь не может скачать HTML, JS и фото напрямую. Скрытый URL и noindex не защищают данные.
- [ ] Сюрприз не раскрывается названием публичного репозитория, preview-уведомлениями или нежелательным общим доступом.
