# ТЗ для внешнего ИИ: производство ассетов Wedding Quest
Версия 1.0. Исполнитель — отдельный ИИ/художник/аудиоинструмент под управлением владельца, НЕ coding-агент. Цель — готовые игровые файлы, а не концепты или промпты. Прочитай GAME_SPEC.md (сюжет, персонажи, навыки, предметы), ART_BIBLE.md и ASSET_HANDOFF.md. Владелец предоставляет разрешённые референсы по PERSONAL_ASSETS_CHECKLIST.md. Не выдумывать личные факты. Не публиковать личные материалы и не использовать музыку без подтверждённых прав. Если инструмент не может экспортировать готовые файлы, сообщить точную недостающую операцию; не выдавать её за выполненную.

## 1. Визуальная система и производство

### 1.1 Art bible

Направление: тёплый 2D pixel art, 16/32-bit эстетика (не аппаратное ограничение), кремовые/золотистые/розовые акценты, зелень и тёмные контуры; более прохладная глава 2, тёплый финал. Крупные читаемые силуэты. Базовая логическая сцена 640×360; tile 16×16; ориентир: персонажи 48 px высотой в кадре 64×64, коты 20–28 px, бульдог 28–36 px; все размеры утверждаются на первом срезе. UI допускает высокое разрешение. Ближайшая фильтрация для pixel-спрайтов; целочисленный масштаб по возможности, иначе пропорциональное FIT с проверкой мобильной читаемости. Не растягивать независимо по осям. Референсные листы содержат фронт/профиль, палитру, рост, особенности, без использования случайных лиц. Сначала утвердить внешний вид пяти героев, затем тиражировать анимации. Для каждого героя закрепить базовый нейтральный спрайт, seed/параметры (если инструмент предоставляет), эталон и промпт. Не полагаться на seed как на гарантию идентичности.

### 1.2 P0/ P1 ведомость генерации

| Группа | P0 минимум | P1 дополнительно |
|---|---|---|
| Невеста, жених | По 1 эталону; по 7 анимаций: idle 4, run 6, jump 2, fall 2, attack 5, skill 6, hurt 2 (27 кадров на героя) | land 3, celebration 4, отдельные переходы |
| Два кота, бульдог | По эталону; idle 4, follow 6, jump 2, ability 4, celebration 3 (19 кадров на питомца) | Сон, умывание, характерные idle |
| NPC | 3 архетипа; idle 3, walk 4, telegraph 3, attack 4, recover 2, defeated 3 (19 кадров/архетип) | Дополнительный NPC, вариации одежды |
| Сюжетные NPC | Гость, силуэты 2–3 типов, портреты при необходимости | Персонализированные гости по согласованию |
| Окружение | 3 tileset (зал, двор, гардероб), 3×3 параллакс-слоя, 12–20 декораций/тема, отдельные интерактивные объекты | Дополнительный передний декор |
| Предметы | Торт, фото, улика, ключ/бирка, коробочка, два кольца, чекпоинт, 4–6 интерактивных объектов | Кофе, напиток, сердечки |
| VFX | След букета, пируэт, удар, рывок, пыль, звёзды, подсветка цели, мягкий эффект вспышки, получение предмета | Дополнительные частицы/конфетти |
| UI | Логотип, 5 портретов, HP, 3 иконки навыков, кнопки, диалоговая рамка, загрузка | Нарядные рамки галереи |
| Сценки | Пролог, переходы (можно на игровых ассетах), финальная пиксельная сцена | Иллюстрации для отдельных переходов |

Ориентир только для персонажной анимации: 54 + 57 + 57 = 168 исходных кадров P0 без сценических NPC; не требовать ровно столько, если качественная анимация достигается меньшим числом. Сначала согласовать эталоны с владельцем и технические параметры с разработчиком; проверить пробную серию до тиражирования. Можно готовить ассеты параллельно с разработкой или до неё.

### 1.3 Pipeline

1. Получить/проверить разрешённые референсы. Выбрать стиль по 2–3 компактным концептам одного экрана; утвердить один. Создать style sheet пяти персонажей и эталонные портреты.
2. Для каждого объекта/анимации фиксировать prompt, reference ID, вид сбоку, направление, размер, palette, число кадров, позу, неизменяемые черты; генерировать отдельные маленькие серии на основе эталона.
3. Экспорт исходников в разрешённое локальное хранилище; удалить фон настоящей alpha-маской, не оставлять клетчатый фон. Проверить отсутствие лишних артефактов, надписей, водяных знаков, случайных объектов. Нормализовать пиксельную сетку, размеры и точки привязки к ногам. Не сжимать спрайт без nearest-neighbor, если это портит стиль.
4. Собрать одинаковые клетки spritesheet или atlas PNG + JSON с именованными кадрами, pivot/trim при необходимости; 1–2 px padding/extrusion для atlas, исключить bleeding. Зафиксировать animation timing, loop, action event marker. Имена `bride/run/00`, `cat_1/ability/00` и т.п.; manifest связывает с игровыми ID. Не привязывать gameplay-урон к случайному кадру: активное окно задаёт конфиг, визуал синхронизируется.
5. Сгенерировать контактные листы/preview анимаций и компоновку на игровом фоне; визуально проверить сходство, ориентацию, дрожание, одинаковую высоту глаз/силуэт, отсутствие смещения ног, цвет, читаемость и повторяемость. При несовпадении исправлять, а не скрывать в игре.
6. Фоны без вшитого интерфейса, текста, героев и обязательных объектов; отдельные tileable слои и props. Tileset должен иметь согласованные края/углы, collision metadata независимы. Фото для воспоминаний не генерировать заново; использовать согласованные оригиналы/кропы.
7. Оптимизировать релизные копии: PNG/atlas для pixel art, WebP/JPEG для фотографий, сохранить прозрачность и цвета. Удалить EXIF/GPS из публикуемых фотографий, проверить выходные файлы. В репозиторий/публичную сборку помещать только утверждённые производные файлы, не исходные личные фото и не временные генерации.

Если внешний ИИ не может экспортировать готовые файлы, использовать другой инструмент/редактор под контролем владельца. Не маркировать незавершённые материалы как готовые; разработчик не заменяет художника.



## 2. Музыка и SFX

P0: три музыкальных композиции минимум (вступление/зал, приключение для глав 1–3 с вариациями/повтором, финал). Рекомендуется пять: menu/prologue, bride, groom, mystery, finale. Лёгкая инструментальная музыка, chiptune/оркестровые мотивы или акустика, без агрессивного саунда. Финал — ваша значимая композиция, если имеется разрешение на выбранный способ использования; иначе собственная/лицензированная инструментальная музыка без имитации конкретного защищённого произведения. Не скачивать аудио со стриминговых сервисов и не обходить DRM. Право прослушивания не равно праву публикации или синхронизации музыки с игрой; проверить условия лицензии (включая частный веб-хостинг). Сохранять источник, лицензию, автора, атрибуцию и ограничения.

| ID | Длительность/режим | Характер |
|---|---|---|
| music_intro | 45–90 s loop | Тёплая свадебная, спокойная |
| music_bride | 60–120 s seamless loop | Лёгкая, игривая |
| music_groom | 60–120 s seamless loop | Энергичная, комичная |
| music_mystery | 60–120 s seamless loop | Любопытство и предвкушение |
| music_finale | 60–180 s, one-shot/согласованное завершение | Эмоциональная, узнаваемый личный смысл |

Минимум SFX: jump, land, attack_bride, attack_groom, hit, hurt, pickup, checkpoint, door, bouquet_return, dash, cat_1, cat_2, bulldog, ring_reveal, ui_confirm, ui_cancel; добавить ambience зала/улицы по P1. Реальные мяуканье/лай необязательны, но повышают персональность. Нужны отдельные файлы, не одна длинная запись всех эффектов.

Исходники WAV 44.1/48 kHz, 16/24 bit или качественный оригинал. Релиз MP3 + Ogg при необходимости и наличии подтверждённой поддержки; не декодировать всё заранее. Проверить стык петли прослушиванием; разработчик дополнительно проверяет его в браузере; при необходимости использовать формат/loop points, позволяющие бесшовное воспроизведение; MP3 может иметь encoder padding. Сводить без clipping, SFX короче и тише при повторе, музыка не перекрывает эффекты, для голосов — субтитры. 
Передать отдельные готовые треки и SFX с длительностью, loop points, авторством и условиями использования. Не подменять отсутствующую композицию случайной музыкой.

## 3. Очерёдность поставки
| Пакет | Содержание | Приёмка владельцем |
|---|---|---|
| A0 | Эталоны пяти персонажей, палитра, композиция экрана | Узнаваемость, единый масштаб, согласованный контракт |
| A1 | Невеста, первый кот, первый NPC, зал, предметы и эффекты среза, трек и SFX | Готовая пробная серия, прозрачность, стабильный pivot, preview |
| A2 | Полные серии двух героев, трёх питомцев, NPC, портреты | Все обязательные состояния, стабильный внешний вид |

## 4. Результат
- Готовая папка/архив согласно ASSET_HANDOFF.md, manifest.json, отдельные PNG/JSON/аудиофайлы, preview анимаций и лицензии.
- Все обязательные ID учтены, отсутствующие перечислены отдельно, нет ложной прозрачности и водяных знаков.
- Личные оригиналы остаются отдельно; готовые фото без EXIF/GPS. Все материалы одобрены владельцем.
